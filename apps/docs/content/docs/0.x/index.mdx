title: Formbraid
description: Framework-agnostic form contracts with application-owned components and Effect execution.
---

Formbraid connects portable form contracts to the components your application already owns. Definitions describe values, validation constraints, presentation hints, and groups; descriptors pair them with executable submission callbacks. Effect 4 manages state, validation, execution, and cancellation. React is the current UI binding, not a requirement of the core contract.

You can also write definitions directly, consume a portable descriptor from another library, or run a session without React. Generation and Laravel are optional at runtime.

## Build your form

Register [field and form components](./react/components.mdx), choose an [automatic or custom layout](./react/forms.mdx), and combine related fields with [composite groups](./react/groups.mdx). Your application owns HTML, accessibility, styling, and any third-party widgets.

Formbraid validates on submission. [Client constraints](./validation.mdx) provide feedback; your backend remains authoritative for validation and authorization. Use a [callback](./submission/callbacks.mdx) or typed [Effect operation](./advanced/headless.mdx). The optional Composer integration emits [Fetch or Inertia callbacks](./submission/inertia.mdx) after Vite statically inspects your components and writes metadata. No runtime submission registry or transport package is required.

## Current release line

These guides describe the `0.x` API and Effect `4.0.2`. The packages are currently local and have not been published to npm or Packagist. React applications use component-only `defineConfig` and import context hooks directly from `@formbraid/react`. Build integrations belong exclusively in Vite. The generator SDK is optional producer tooling; Laravel is distributed only through Composer.

See [development](./development.mdx) to run the example, verify a change, or rebuild this documentation.
