---
title: Generated Fetch and Inertia callbacks
description: Choose a PHP submission generator without installing a runtime adapter.
---

The Composer integration emits executable callbacks into version-1 descriptors. Choose the generator in PHP configuration, not in a React submission registry:

```php title="config/formbraid.php"
'submission_driver' => Formbraid\Laravel\Drivers\Fetch::class,
// Or, for an existing Inertia React application:
// 'submission_driver' => Formbraid\Laravel\Drivers\Inertia::class,
```

Regenerate through Vite after changing this config. The PHP `SubmissionDriver` interface is a code-emission contract, not a JavaScript runtime executor. There is no Formbraid Inertia package, Laravel Node package, named JSON binding, or `bindForm` call.

## Fetch

The default Fetch generator emits self-contained browser code. It uses same-origin credentials and reads the live `XSRF-TOKEN` cookie on every request, URL-decoding its value into `X-XSRF-TOKEN`. Keep the application's normal Laravel session and CSRF middleware; no manual token plumbing is needed.

Generated code serializes supported values, handles multipart uploads and Laravel method spoofing, maps validation errors to `invalid`, maps expected HTTP/network failures to `failure`, and honors the abort signal. Fetch does not provide upload progress events; use Inertia when your application needs its upload lifecycle.

## Inertia

The Inertia generator dynamically imports the application's existing `@inertiajs/react` router. Keep the app's usual Inertia dependencies and server middleware; do not install a separate Formbraid transport or register a driver at runtime. Use normal Inertia responses and validation redirects on the server.

The callback waits for the visit lifecycle, returns success or field errors, forwards upload progress, and connects cancellation to the visit. Errors and cancellation become explicit submission outcomes rather than resolving a promise and assuming success. Session cancellation suppresses late progress and outcomes; it cannot undo a server mutation already accepted.

## Render and observe results

```tsx
import { Form } from './formbraid';
import { update } from './formbraid/laravel/controllers/App/Http/Controllers/ProfileController';

<Form
    form={update({ user: 42 })}
    onResult={(result) => {
        if (result.status === 'success') showSavedMessage();
    }}
    onProgress={(progress) => showUploadProgress(progress)}
/>;
```

`showSavedMessage` and `showUploadProgress` are application functions. `update(...)` returns a descriptor directly, not `.form()`. Field errors use `useFieldContext`; root errors use `state.errors['']`. Later edits stay dirty, and stale submitted errors cannot overwrite edited fields.

| Result      | Meaning                                 |
| ----------- | --------------------------------------- |
| `success`   | Authoritative endpoint/visit acceptance |
| `invalid`   | Server validation errors                |
| `cancelled` | Cancelled execution                     |
| `failure`   | Expected transport failure              |
| `defect`    | Unexpected execution defect             |

A local `submit` callback can replace generated execution for one form. Use [callbacks](./callbacks.mdx) for external integrations and [Effect operations](./effect.mdx) for native Effect execution and services.
