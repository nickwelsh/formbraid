---
title: Troubleshooting
description: Diagnose generation, rendering, validation, and submission problems.
---

## A component or prop is rejected during generation

Check the component-only React `defineConfig({ components, formComponents?, groups?, submitComponent? })` and the component's declared props. Keep literal keys and statically inspectable objects. Broad `Record<string, ...>` annotations erase useful names. Unknown components, unknown props, missing required props, and incompatible prop values are errors.

If a wrapper or dynamic construction prevents static inspection, simplify the registration. Vite inspects types without evaluating UI modules, CSS imports, or browser globals. Build integrations belong in Vite, not React config.

## Metadata or the generated enum is missing

Start Vite once. Only Vite produces `_metadata.json`; `php artisan formbraid:generate` consumes JSON and deliberately fails without it. Check Vite registration, the descriptor's registry/metadata URLs, and filesystem access. Do not fabricate JSON or expect Artisan to inspect TypeScript.

`component_enum` is an output path (default `app/Formbraid/FormField.php`), not a class name. One merged string-backed enum covers fields, form components, and groups, with namespace inferred from Composer PSR-4. Keep initial mappings as strings so Laravel can bootstrap; use generated cases after the first metadata pass. Clear cached config after changing it.

## A form renders but cannot submit

A bare definition supports local editing and validation. Supply a callback descriptor with `submission: { submit }`, a local `submit` callback, or an Effect `operation`. There is no runtime submission registry or named JSON binding. Callbacks must return explicit results; promise resolution alone is not success.

For generated controller descriptors, the routed method must reference a discovered FormRequest. Import from the namespace-preserving `controllers/...` module and call `update({ user: 42 })`, not `.form()`.

## Defaults change but the draft does not reset

Defaults initialize a mounted session. Rerendering does not discard edits. Use a React `key` when changing records, or call `form.reset(values)` deliberately. The precedence is explicit defaults, descriptor defaults, then definition defaults.

## Server errors appear in the wrong form

Each mounted form owns a session. Ensure your callback maps only the current operation's validation response. Field errors use canonical paths; root errors use the empty path. Errors from a submitted draft do not replace fields edited since that submission. Inertia applications should also follow their existing server-side error scoping conventions.

## A rule is not enforced in the browser

Generation reports constraints that cannot be represented on the client. Unique/existence queries, custom rules, closures, request-dependent conditions, and file content/size checks remain server responsibilities. Validation runs on submit, not on each edit or blur. See [validation](./validation.mdx).

## A nested write creates an object instead of an array

Use a schema, generated metadata, or initialized baseline that identifies the container shape. If the shape cannot be inspected, initialize the array through `append` or a whole-field update. Optional containers and dynamic indexes can return `undefined` when read.

## Cancellation does not undo a mutation

Cancellation interrupts local execution and suppresses stale results. A transport must honor the abort signal and release its own resources. The server may already have accepted the write; handle rollback or compensation in the application when required.

## Generated files are refused or stale

Run the application's Vite build to refresh metadata and generation, then review emitted definitions, controller descriptors, the merged enum, and obsolete outputs. Generated files are hash-owned; a marker alone does not authorize overwriting an edited or unowned file. Move application code out of generated paths and resolve ownership conflicts deliberately. Do not weaken hashes to force an overwrite. Init scaffolds are user-owned and preserve edits on reruns.

If new PHP modules do not regenerate, check `requests` (directories or PHP globs such as `app/Modules/**/Requests/**/*.php`) and descriptor watch patterns. Keep generated TypeScript and enum paths in `outputs` to avoid watch loops. Component import dependencies and PHP events are watched and coalesced by Vite.

## Documentation generation fails

Run `pnpm docs:api` to isolate Refquill analysis from MDX rendering. All inputs must produce public declarations. Resolve TypeScript diagnostics and invalid metadata before rebuilding; failed generation preserves the previous JSON output. Use `pnpm docs:build` for the complete API, site, and Worker packaging pipeline.
