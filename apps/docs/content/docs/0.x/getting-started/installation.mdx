Packages have not yet been published to npm or Packagist. Use workspace dependencies, local package archives, or a Composer path repository until publication. The install commands below identify the packages your application needs.

## Requirements

- Node.js 24.11 or newer and the pnpm version pinned in the root `package.json` for this repository's tooling.
- React 19 and Effect `4.0.2` for React forms.
- PHP 8.3 or newer, Composer, and Laravel 12 or 13 for the optional Laravel integration.
- PHP 8.4.1 or newer for this checkout's locked development dependencies; CI uses PHP 8.4.
- Vite+ for repository development and package builds.

## Runtime packages

```sh
pnpm add @formbraid/core @formbraid/react effect react
```

`@formbraid/core` contains framework-agnostic definitions, callback descriptors, validation, and headless sessions. `@formbraid/react` supplies the current UI binding. Generation and Laravel are optional.

`@formbraid/core/vite` is a Node-only core subpath for build integrations, not another package to install. `@formbraid/generator` is an optional producer-author SDK re-exporting that tooling; applications do not need it. There is no generator CLI, Laravel Node package, or Formbraid Inertia adapter to install. An existing Inertia app uses its own `@inertiajs/react` dependency.

## Build local archives

```sh
git clone https://github.com/nickwelsh/formbraid.git
cd formbraid
vp install --frozen-lockfile
composer install --working-dir=packages/laravel
vp run build
```

Within this workspace, use `workspace:*` dependencies. Outside it, pack the required packages after building and install the archives together. pnpm's packing process replaces workspace dependency references.

## Optional Laravel integration

In your Laravel application's `composer.json`, register the local checkout as a path repository:

```json
{
    "repositories": [{ "type": "path", "url": "../formbraid/packages/laravel" }]
}
```

```sh
composer require formbraid/laravel:@dev
php artisan formbraid:init --register-vite
```

Laravel discovers the provider automatically. Init creates config and editable frontend files beside the configured metadata path, preserves existing files, and prints manual Vite registration when automatic registration is unsafe. It never creates fake metadata. Review config mappings and scaffolded controls, then start your application's Vite dev server once to produce metadata and run PHP generation. See the [quickstart](./quickstart.mdx).

To publish only config, `php artisan vendor:publish --tag=formbraid-config` remains available. It does not scaffold components or produce metadata.

## Bundled example

```sh
vp run dev
```

Vite produces metadata and runs the example's PHP generation command. The example uses a lightweight PHP application and a generated Fetch callback; no generator CLI is needed. Run its PHP backend as described in [development](../development.mdx) to exercise submission. Connect your preferred address provider for production.
