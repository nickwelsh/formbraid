## Definitions describe editable values

A `FormDefinition` names fields, defaults, constraints, presentation metadata, and groups. It can include a native Effect schema for validation and transformations. The core contract does not require React, Laravel, or a generator. React is the current UI binding; producers can target the contract without depending on the application's component configuration.

## Descriptors carry executable callbacks

A version-1 `FormDescriptor` is `{ version: 1, definition, defaultValues?, submission: { submit } }`. The callback receives decoded values and `{ signal, onProgress }`, then returns an explicit `SubmissionResult` or `PromiseLike<SubmissionResult>`. Laravel controller functions return descriptors directly, such as `update({ user: 42 })`.

There is no runtime submission-driver registry, named JSON binding, `bindForm`, or executable JSON descriptor parser. A local `submit` callback or typed Effect `operation` can override execution for one instance. [Portable descriptors](../advanced/descriptors.mdx) explain defaults, lifetime, and producer boundaries.

## Sessions own editing and execution

`createFormSession` owns the editable draft, baseline, touched state, errors, progress, and execution state. React's `Form` or `useForm` creates one session per mounted form and exposes selected snapshots through contexts and subscriptions.

Submission captures the draft, decodes it, then executes a callback or operation in an interruptible Effect. Duplicate submissions share active work. Success commits the submitted baseline; later edits remain dirty. Cancellation suppresses late outcomes and progress. Keep one editable-value store rather than synchronizing a second draft with Formbraid.

## Build integrations stay out of the runtime

React's `defineConfig({ components, formComponents?, groups?, submitComponent? })` returns `{ Form, useForm }` and registers only components. Build integrations belong exclusively in Vite:

```ts
import { vitePlugin as formbraid } from '@formbraid/core/vite';
import laravelForms from './resources/js/formbraid/laravel';

// Inside the existing Vite plugins array:
formbraid({ integrations: [laravelForms] });
```

The build-only `Integration` descriptor supplies registry and metadata URLs, a command, PHP/input watch patterns, and output exclusions. Vite statically inspects component types without executing CSS imports or browser globals, atomically writes metadata, then runs the backend command. Component imports and PHP changes are watched and coalesced. Artisan consumes finished JSON; it cannot inspect TypeScript or refresh metadata.

| Entry point            | Responsibility                                                              |
| ---------------------- | --------------------------------------------------------------------------- |
| `@formbraid/core`      | Framework-agnostic contracts, validation, scoped Effect sessions            |
| `@formbraid/react`     | Contexts, subscriptions, typed components, layouts, groups                  |
| `@formbraid/core/vite` | Node-only integration contracts, static inspection, Vite plugin             |
| `@formbraid/generator` | Optional producer-author SDK re-exporting core's Vite tooling               |
| `formbraid/laravel`    | Composer scaffolding, extraction, enums, TypeScript and callback generation |

Applications need no generator SDK, Laravel Node package, or Formbraid Inertia package. The PHP integration can emit callbacks using Fetch or an existing Inertia React app's router.

## Trust boundaries

Validate external metadata at the producer boundary, then attach trusted execution code. JSON cannot carry executable callbacks. Backend validation and authorization remain authoritative; successful client decoding cannot prove access, uniqueness, or server acceptance. Return success only after authoritative acceptance. Aborting a local wait cannot undo a durably queued or accepted mutation.
