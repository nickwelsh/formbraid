Requires Node 24.11+, pnpm (the pinned version is in `package.json`), Vite+ (`vp`), PHP 8.4.1+ for the locked development dependencies, and Composer. The PHP package supports PHP 8.3+; CI uses PHP 8.4.

```sh
vp install
composer install --working-dir=packages/laravel
vp run build
vp run dev
```

Vite produces component metadata and invokes PHP generation for the example's lightweight application. To exercise the generated Fetch callback, run the PHP backend in a second terminal:

```sh
php -S 127.0.0.1:8000 -t examples/react/public examples/react/public/index.php
```

Vite proxies submission and CSRF-cookie routes to that backend. The address lookup uses a fixed sample suggestion; connect your preferred provider in application code. There is no generator CLI or separate React generator pipeline.

```sh
vp check
vp exec tsc --noEmit
vp test run
composer --working-dir=packages/laravel test
composer --working-dir=packages/laravel check
php packages/laravel/vendor/bin/pint --test packages/laravel/src packages/laravel/tests examples/react/php
```

To refresh generated example outputs, run its Vite build and review the worktree. Standalone Artisan generation consumes existing JSON and cannot refresh component metadata. Missing metadata means Vite must run once; do not create placeholder JSON. Generated outputs are hash-owned and reject edited/unowned collisions, while init scaffolds remain user-owned. In environments that restrict local sockets, add `--debug --no-progress` to PHPStan to run without worker processes.

## Build documentation

```sh
pnpm docs:dev
pnpm docs:api
pnpm docs:build
pnpm docs:check
pnpm --filter @formbraid/docs deploy:check
```

The docs app consumes `@nickwelsh/docs-base` for layouts, navigation, MDX, search, code rendering, and Markdown exports. Authored content lives in `apps/docs/content/docs/0.x`. Folder `meta.json` files order navigation. Add a new version folder when a new API line needs separate guides.

Refquill analyzes the repository's public TypeScript entry points and Laravel PHP sources on every documentation build. Its JSON is generated into ignored `apps/docs/generated/api.json` and rendered under the API reference section. API declarations, source locations, signatures, and PHP methods come from the code being built. Keep explanatory comments next to public declarations; use guides for workflows spanning several APIs.

The build then prerenders the site and packages an assets-only Cloudflare Worker using the public `/formbraid` prefix. Local `docs:dev` generates references before starting; run `docs:api` again after API edits.

## Continuous integration and releases

The Check workflow verifies TypeScript, package builds, generated example output, PHP, and documentation on every push and pull request. It tests the packaged docs in the Workers runtime and validates the deployment artifact without credentials. Release deployment waits for both the TypeScript and PHP jobs. npm publication covers core, React, and the optional generator SDK; the sole Laravel integration is the Composer package.

Only pushed release tags matching `v*` deploy to `https://docs.nickwelsh.me/formbraid`. The deploy job uses the exact artifact that passed the docs build and dry run. Configure the GitHub `cloudflare` environment's `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID` before the first release. The token needs Workers Scripts Edit and zone Workers Routes Edit, plus Zone Read for route discovery.

The documentation site represents the latest deployed release for each authored version line. Ordinary branch pushes validate changes without changing the published site. See [the docs app README](https://github.com/nickwelsh/formbraid/blob/main/apps/docs/README.md) for hosting prerequisites and redeployment instructions.
