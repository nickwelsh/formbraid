description: Scaffold editable components, let Vite produce metadata, and let PHP generate owned outputs.

## Scaffold user-owned files

```sh
php artisan formbraid:init --register-vite
```

Init creates `index.ts`, `fields.tsx`, `form-components.tsx`, and `laravel.ts` in `dirname(config('formbraid.metadata'))`, defaulting to `resources/js/formbraid`. It preserves existing files and user edits on reruns. It does not create fake metadata or overwrite generated files to resolve collisions.

`index.ts` exports `{ Form, useForm }` from React's component-only `defineConfig({ components, formComponents?, groups?, submitComponent? })`. Keep keys literal and declarations statically inspectable. Submission/build integration registration does not belong there.

The optional `--register-vite` modifies only a standard literal `defineConfig({ plugins: [...] })`. Complex configurations get manual instructions instead. Register alongside existing plugins:

```ts title="vite.config.ts"
import { defineConfig } from 'vite';
import { vitePlugin as formbraid } from '@formbraid/core/vite';
import laravelForms from './resources/js/formbraid/laravel';

export default defineConfig({
    plugins: [formbraid({ integrations: [laravelForms] })],
});
```

## Build-only descriptor

```ts title="resources/js/formbraid/laravel.ts"
import type { Integration } from '@formbraid/core/vite';

export default {
    name: 'laravel',
    registry: new URL('./index.ts', import.meta.url),
    metadata: new URL('./_metadata.json', import.meta.url),
    command: ['php', 'artisan', 'formbraid:generate'],
    watch: ['app/**/*.php', 'routes/**/*.php', 'config/formbraid.php'],
    outputs: ['resources/js/formbraid/laravel/**', 'app/Formbraid/FormField.php'],
} satisfies Integration;
```

Init also adds configured request patterns to `watch`. The descriptor imports no UI modules, so it is safe to load during a build. Registry/metadata URLs are relative to it; watch/output paths and command execution use the Vite root. Keep exclusions in sync if changing output paths.

## Vite is the only metadata producer

Start the application's usual Vite dev command, or run its Vite build. Vite statically inspects TypeScript without evaluating component modules, CSS imports, or browser globals. It atomically writes `_metadata.json`, then invokes Artisan. In dev, component imports and PHP patterns are watched, including new app module directories; changes coalesce and generated outputs do not loop back into generation.

Artisan consumes JSON only. `php artisan formbraid:generate` can rerun PHP generation against an existing snapshot, but cannot refresh component metadata. If the snapshot is missing, **start Vite once**. Do not handwrite placeholder JSON. No generator CLI or React generator adapter is required.

## Bootstrap and generated paths

Keep initial PHP field mappings as strings until the first pass. PHP merges frontend fields, form components, and groups into one string-backed enum at `component_enum` (default `app/Formbraid/FormField.php`). Composer PSR-4 determines its namespace. After generation, use its cases in request `fields()` / `groups()` or config mappings.

Request definitions use `defineForm` and preserve fully qualified namespaces as directory segments:

- `requests/App/Http/Requests/UpdateProfileRequest.ts`
- `controllers/App/Http/Controllers/ProfileController.ts`

These paths are under the configured `output`, default `resources/js/formbraid/laravel`. A routed controller method accepting a discovered FormRequest produces a descriptor factory:

```tsx
import { Form } from './formbraid';
import { update } from './formbraid/laravel/controllers/App/Http/Controllers/ProfileController';

<Form form={update({ user: 42 })} defaultValues={values} />;
```

For a route without parameters, the export is the descriptor itself: render `<Form form={update} />`. Parameterized functions return descriptors directly, not `.form()` helpers or named driver bindings. The descriptor contains a definition and emitted `submission.submit` callback. Bare request definitions can render for local editing/validation; provide a local callback or Effect operation for execution when there is no controller descriptor.

## Protect generated ownership

Generated outputs are hash-owned through a manifest, including the enum. Generation refuses to overwrite edited or unowned files and refuses to silently remove edited obsolete files. A generated marker alone is not permission to overwrite a file. Review conflicts and move application code out of output paths; never resolve them by falsifying ownership hashes.

Scaffold files are user-owned and deliberately excluded from generated ownership. Customize those controls and producer config, then let Vite regenerate. In CI, run the application's Vite build to refresh metadata and generation before checking the worktree for output drift; there is no legacy `formbraid generate --check` CLI.
